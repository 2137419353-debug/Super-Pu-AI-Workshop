# 大圃 · 微信风 AI 协作空间（组装 timer + pre + task + sum + research · v9）

一个单体 Streamlit 应用：把「微信群聊」做成 AI 协作空间——群主自带 DeepSeek API Key（BYOK），在群里召唤大圃（🤖）就能跑真实技能，成果以文件形式进入右侧成果篮。

本版（**v9**）在 v8（timer + pre + task + sum 组装 + 输入区死保 + 零原生提示 + 静默自动刷新 + 左侧静态渲染 + 本地 Mermaid）基础上，把**深度调研**正式接入成第 5 个插件化技能：

1. **独立黑盒**：`research_skill.py` 从 `skill-searcher_v02` 提取，去掉全部 Streamlit 代码，入口 `run_skill(topic, api_key) -> {text, mermaid_code, word_bytes}`；Prompt 文件独立为 `SKILL_research.md`（避免与 Pre 技能的根 `SKILL.md` 重名）；
2. **注册为技能**：`SKILL_REGISTRY` 新增 `RESEARCH`（name / icon / desc / renderer / history），左侧自动生成「🔎 深度调研」卡片，展开即内联预览标题 / 摘要 / 结构统计 / 关键词关系图 / 八维正文；
3. **召唤 + 路由**：召唤弹窗可手动选「🔎 深度调研」，自动识别也可由大模型路由到 `RESEARCH`；
4. **后台写回**：调研结果在后台线程里写回成果篮 Word + 群聊 AI 气泡（含调研标题 / 摘要 / 文件名）；
5. **兜底不花钱**：路由失败 / `UNKNOWN` 时仍兜底「本地占位调研」（不调用模型、不产文件、不进左侧调研卡片），只有手动选择或路由真正命中 `RESEARCH` 时才真实调用。

| 能力 | 实现状态 |
| --- | --- |
| 🩺 Pre 建议（Pre 逻辑教练） | **真实**：DeepSeek + 移植 `py-precoach_v02` 核心（`precoach_skill.py`） |
| ⏱ 日程提取（生成 `.ics`） | **真实**：DeepSeek 提取，文件名按真实日程日期动态计算 |
| 🧩 任务拆解（Task Board） | **真实**：DeepSeek + 移植 `py-taskboard_v03` 核心（`taskboard_skill.py`），只进左侧卡片 |
| 📝 复盘总结（Summary） | **真实**：DeepSeek 复盘真人聊天记录，产出 Word（`summary_skill.py`）；卡片 / 召唤 / 路由 / 🛑 按钮四条入口复用同一黑盒 |
| 🔎 深度调研（Research） | **真实**：DeepSeek 生成八维调研报告并排版 Word（`research_skill.py` + `SKILL_research.md`）；路由失败时降级本地占位 |

> **5 项真实技能**全部注册在左侧面板（Pre 诊断 / 日程提取 / 任务拆解 / 复盘总结 / 深度调研）；路由失败时的「本地占位调研」不是技能，不出现在面板里。
> 成果篮只收录 **AI 生成的 Word / ICS**；用户上传的原始文件、Markdown、只有正文没有文件的成果都不会出现。

## 1. 60 秒启动（Windows PowerShell）

```powershell
# 1) 进入交付根目录（本 README 所在目录，按你解压后的实际路径调整）
cd "<交付根目录>"

# 2) 创建并激活虚拟环境（只做一次）
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 3) 安装依赖（只做一次）
python -m pip install --upgrade pip
python -m pip install -r requirements.txt

# 4) 启动应用
python -m streamlit run app.py
```

也可以直接双击 `启动.bat`：它会优先使用 `.venv\Scripts\python.exe`，没有虚拟环境时回退系统 `python`，效果等同于 `python -m streamlit run app.py`。

启动后终端会打印 `Local URL: http://localhost:8501`，浏览器一般会自动打开；没有就手动访问 <http://localhost:8501>。

> **准备 API Key**：到 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys) 创建一个 Key。
> 建群时填写，房间内所有真实 AI 调用（大模型意图路由 / Pre 诊断 / 日程提取 / 任务拆解 / 复盘总结 / 深度调研）都使用它。
> Key 只保存在当前 Python 进程内存，不写入磁盘、不进日志、不进生成的文件。
>
> 若第 2 步提示「禁止运行脚本」，先执行 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` 再重新激活。
>
> 不想激活虚拟环境？用 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` 和 `.\.venv\Scripts\python.exe -m streamlit run app.py`。

### 运行环境与依赖

- Python **3.10+**（推荐 3.11 / 3.12；本次交付在系统 Python 3.14.7 上实测）；
- `requirements.txt`：`streamlit==1.62.0`、`requests>=2.31,<3`、`python-docx>=1.1,<2`、`python-pptx>=1.0,<2`、`openpyxl>=3.1,<4`（Excel 解析；**不依赖 pandas**）；
- 运行应用的机器需能访问 DeepSeek API（`api.deepseek.com`，意图路由与 5 个技能都会用到）；
- **必须一起打包 `static/mermaid.min.js`**（本地 Mermaid 资源，2,571,900 bytes / 约 2.45 MiB），否则 Pre 诊断的逻辑链会降级为 `st.markdown` 源码块展示。

## 2. 三栏布局与左侧技能卡片

进入房间后是三栏布局（左右等宽，中间主舞台；宽度权重 `st.columns([1.8, 3.2, 1.8], gap="large")`）：

| 区域 | 宽度权重 | 内容 |
| --- | --- | --- |
| 左侧 | 1.8 | 通讯录 + 由 `SKILL_REGISTRY` 生成的技能卡片（Pre 诊断 / 日程提取 / 任务拆解 / 复盘总结 / 深度调研） |
| 中间 | 3.2 | 群聊消息流（固定高度滚动区）+ 底部「✨ 召唤大圃 / 🛑 总结会议 / 聊天输入」 |
| 右侧 | 1.8 | 成果篮（AI 生成的 Word / ICS，纵向文件卡） |

**左侧技能卡片怎么用**：

1. 每张卡片是一个可展开的 `Expander`，标题形如「🩺 Pre 诊断」「⏱ 日程提取」「🧩 任务拆解」「📝 复盘总结」「🔎 深度调研」；**首次进入时若有历史默认展开**，之后展开 / 收起状态由 `session_state` 持久化——自动刷新 / 整页 rerun 不会把它收起来，也不会闪烁；
2. 展开后第一行是 **「✨ 召唤大圃执行{技能名}」** 绿色渐变按钮——点击会打开召唤弹窗，并**自动预设**对应技能；
3. 按钮下方内联展示该技能的历史预览：
   - 🩺 Pre 诊断：主题 / 阶段 / 发起人，Mermaid 逻辑链图（本地资源渲染），完整诊断正文；
   - ⏱ 日程提取：已提取的日程列表（时间、事件、地点）；
   - 🧩 任务拆解：任务卡（徽标 / 截止 / 标题 / 进度条 / 可勾选子任务）+ 内联详情（核心目标 / 拆解清单 / 预期产出 / 截止时间 / 寄语）；
   - 📝 复盘总结：复盘主题、来源（🛑 总结会议 / ✨ 召唤大圃）、发起人与时间、共识 / 否决 / 待议完整正文、Word 文件名；
   - 🔎 深度调研：调研标题 / 副标题、约多少字 / 多少张表 / 多少条来源 / 三档可信度数量、关键词关系图（本地 Mermaid）、八维报告完整正文、Word 文件名；
4. 没有历史时显示空态提示，卡片默认收起；
5. **字体规则**：展开区正文 / 列表 12.5px，标题 h1 16px、h2 14.5px、h3 13px，复选框标签 12.5px；左侧字号不会大于中间聊天框；
6. **自动刷新 / 防闪烁**：左侧面板本体是静态渲染（不参与 2 秒轮询）；旁边一个不可见的 watcher 每 2 秒比较数据指纹——没有新文件 / 新任务 / 新日程 / 新成员时不会重绘、不会 rerun，用户的展开状态也不会被重置。

> 从**左侧技能卡片**进入弹窗时，弹窗会预设该技能；从**中间「✨ 召唤大圃」**进入时，默认回到「自动识别（AI 判断）」。

## 3. 使用流程

1. **打开首页** → 点「🚀 开始工作」。
2. **选身份**：群主点「👑 我是群主」；被邀请的伙伴点「🫱 我是成员」。
3. **建群（群主）**：填写群聊名称、你的昵称、**DeepSeek API Key** → 「创建群聊 →」；
   创建成功页会给出专属邀请链接，可一键复制发给伙伴（成员打开链接、填昵称即可入群）。
   校验不通过时（群名 / 昵称长度、Key 为空、邀请链接格式不对），只在表单下方出现一行「⚠️ …」小字提示，不弹出任何对话框。
4. **进房间**：三栏布局；左侧技能卡片初始为空态，成果篮为空；中间底部始终有「✨ 召唤大圃」「🛑 总结会议」和聊天输入框。
5. **召唤大圃**：点中间「✨ 召唤大圃」或左侧任意技能卡片的召唤按钮，粘贴长文、上传附件（`docx / pptx / xlsx / txt / md`），选择技能：
   - **自动识别（AI 判断）**：调用 DeepSeek 大模型做意图路由，返回 `PRECOACH / TIMER / TASK_CARD / SUMMARY / RESEARCH` 之一（需要群主 Key；失败或无法匹配时兜底为「深度调研」本地占位）；
   - **手动指定**：「🩺 Pre 诊断 / ⏱ 日程提取 / 🧩 任务拆解 / 📝 复盘总结 / 🔎 深度调研」——直接执行所选技能，**不调用路由模型**。
6. **提交后立即返回**：点「🚀 交给大圃」后弹窗**立刻关闭**；群里马上出现一条 AI 气泡「🤖 收到，大圃正在处理中，完成后直接在这里回复你。」，后台开始解析附件、判定意图、调用技能。
   - 处理完成：群内出现结果提醒（核心目标 / 数量 / 文件名等），左侧卡片和成果篮自动更新；
   - 处理失败：群内出现「⚠️ 失败原因」AI 气泡（例如材料没通过 Pre 前置校验、没有 API Key、附件过大）；
   - 全程**不需要手动刷新**：聊天与成果篮各自每 2 秒静默轮询；左侧面板是静态渲染，只有真正出现新文件 / 新任务 / 新日程 / 新成员时，watcher 才会触发一次整页刷新（平时每 2 秒视觉零变化）；
   - 等待期间可以继续发群聊消息、继续打字，底部输入区不会被挤占或闪烁。
   - 如果召唤弹窗里什么都没填就提交，弹窗直接关闭，群里会收到一条 AI 气泡提醒「请先粘贴一段文字，或上传一个文件，再交给大圃。」。
7. **看结果**：
   - 任务拆解：左侧「🧩 任务拆解」卡片内出现任务卡（可勾选），**不生成文件**；
   - Pre 诊断：左侧「🩺 Pre 诊断」卡片内直接看主题 / 阶段 / 逻辑链 / 完整正文；成果篮出现 `{主题}·Pre建议.docx`；
   - 日程提取：左侧「⏱ 日程提取」卡片内出现日程列表；成果篮出现 `.ics`；
   - 复盘总结：左侧「📝 复盘总结」卡片内直接看共识 / 否决 / 待议正文；成果篮出现 `{概括文件名}.docx`；
   - 深度调研：左侧「🔎 深度调研」卡片内直接看摘要 / 结构统计 / 关系图 / 八维正文；成果篮出现 `{调研标题}_{日期}.docx`；
   - 深度调研（路由失败兜底）：群内出现本地占位正文，**不生成文件**，也不进左侧调研卡片。
8. **勾选任务**：在左侧任务卡里逐条勾选，勾选写回服务端房间状态；刷新页面或群成员下一次交互即可看到同一进度。
9. **会议结束**：点「🛑 总结会议」，大圃抓取真人聊天记录生成复盘总结（Word 进成果篮；这一步在页面内同步执行）。
   - 等价于召唤「📝 复盘总结」技能并自动带上「结束讨论并总结」提示词；两条路径产出的复盘都会进入左侧「📝 复盘总结」卡片与成果篮；
   - 没有可总结内容 / 没有 API Key / 总结失败：都会在群里收到一条 AI 气泡说明原因，不会弹出提示框。
10. **下载成果**：成果篮每张文件卡是纵向结构——第一行是图标 / 文件名 / 类型与大小（长文件名省略号、悬停看全名），第二行整行「📥 下载文件」按钮。

### 成果篮收录规则

- 只收录 **Word（`.docx`）/ ICS（`.ics`）** 两类 AI 生成文件；
- 用户上传的原始 `docx / pptx / xlsx / txt / md` 只用于本次文本解析，**不进成果篮**；
- Markdown（`.md`）即使由 AI 生成也不进成果篮；
- 只有正文、没有文件字节的成果（如深度调研占位、任务卡）不进成果篮；
- 同一文件名 + 大小的产出会自动去重。

## 5. 意图路由说明

召唤弹窗的「交给哪个技能」有两类行为：

| 选择 | 行为 |
| --- | --- |
| 自动识别（AI 判断） | 用 DeepSeek 大模型判断意图：读取材料前 6,000 字符 → 返回严格 JSON → 取 `intent` / `confidence` → 路由到对应技能 |
| 手动指定某个技能（含从左侧卡片进入时的预设） | 直接把意图固定为所选技能（`confidence = 1.0`），**不调用路由模型** |

- 路由模型：`deepseek-chat`，`temperature=0.1`，`max_tokens=200`，非流式，要求只输出一个 JSON；
- 合法意图：`PRECOACH / TIMER / TASK_CARD / SUMMARY / RESEARCH`；模型返回 `UNKNOWN` 表示闲聊或无匹配；
- **判定优先级**：拆任务 → `TASK_CARD`；改汇报 / 路演 / Pre → `PRECOACH`；日期 + 会议通知 → `TIMER`；复盘 / 会议纪要 / 总结讨论 / 提取共识 → `SUMMARY`；调研 / 竞品 / 行业研究 → `RESEARCH`；
- **兜底规则**：无 API Key、材料为空、网络异常、HTTP 非 200、响应不是合法 JSON、缺少 `choices`、`intent` 非法或为 `UNKNOWN` —— 一律兜底为 **`RESEARCH`（深度调研，本地占位），置信度 0.5**；
- **真实调研的触发条件**：手动选择「🔎 深度调研」、或路由**明确**返回 `RESEARCH` 时才调用 `research_skill` 并产出 Word；兜底（`matched=False`）只写本地占位正文，不调用付费 API；
- 路由只决定「交给谁」；真正的技能调用仍使用群主 Key 真实调用 DeepSeek。

> 因为兜底是「本地占位调研」，路由失败或模型判定为闲聊时，你会看到一条本地占位的深度调研正文，而不是报错，也不会产生费用；重新召唤并手动指定技能即可。

## 6. 任务拆解（Task Board）技能说明

任务拆解是真实技能：核心层在 `taskboard_skill.py`（不 import `streamlit`、无任何 UI 依赖），网页层只负责调用与展示。

### 6.1 输入要求

- 在召唤弹窗里粘贴讨论记录、任务描述或背景材料即可；**短输入可以直接提交**（例如只说「任务卡」也会真实到达 API）；
- 网页端粘贴框上限 **12,000 字符**（`max_chars = 12000`）；粘贴文字与附件解析结果合并后由 `_clip_extracted` 截到 **30,000 字符**（超出会附系统提示）；
- 进入任务拆解技能前，`app.run_taskboard_skill()` 在材料 `len > 19,900` 时截断到 **19,900 字**并追加提示「【系统提示：材料超过任务拆解技能 20,000 字上限，已截断保留前 19,900 字。】」；
- 技能核心 `taskboard_skill.run_skill()` 自身硬上限 **20,000 字**；直接调用核心层时超出会报错「初稿最多 20000 字，请精简后再试」；
- 输入为空时不会调用技能；房间没有可用 API Key 时，后台失败原因会以「⚠️ …」AI 气泡出现在群里。

### 6.2 输出卡片协议

System Prompt 由「`SKILL_taskboard.md` 原文 + 最高优先级输出铁律」拼成，要求模型只输出一张卡片（禁止问候、追问、代码围栏、思考过程）：

| 字段 | 要求 |
| --- | --- |
| 本次核心目标 | 一句话概括讨论要达成的结果 |
| 目标拆解清单 | **3–5 条**子任务，必须用 `- [ ]` 语法；每条 **≤10 个汉字**，只保留「动词 + 名词」的核心动作；禁止括号、破折号、从句、解释、举例、执行细节 |
| 预期产出 | 具体的文件或成果 |
| 截止时间 | 提取出的时间；无法确定时写「未设定」，禁止编造日期 |
| 多语种寄语 | 外语原文 / 中国古诗词 + 作者或出处 + 中文译文；译文直接写成 `*（……）*`，**不得出现「中文翻译」标签，不得输出「微解」字段** |

### 6.3 模型输出物理清洗

`run_skill()` 不信任模型输出，解析前先做物理清洗：截出 `【团队协作任务卡片】` 之后的部分并去掉代码围栏 / blockquote；用字段正则提取核心目标 / 预期产出 / 截止时间 / 寄语 / 作者 / 译文；子任务去括号 / 破折号 / 举例从句并压到 **10 个可见汉字**以内，再去重、校验 **3–5 条**；按协议字段重建卡片 Markdown；缺少核心目标或子任务不足时报可读错误，不把半成品写进看板。

### 6.4 任务卡与勾选同步（左侧卡片内联）

- 任务卡显示在左侧「🧩 任务拆解」Expander 内，展开即预览：`AI` 徽标、截止时间、标题、进度条（`已完成 x/n 项`）、可勾选子任务，以及内联详情（🎯 核心目标 / 📝 拆解清单 / 📦 预期产出 / ⏰ 截止时间 / 📜 寄语）；
- 勾选写回 `ServerState.set_task_acceptance()`（服务端房间状态），多个标签页 / 群成员共享同一份进度；
- 任务卡**不产出任何文件**，成果篮不会出现任务卡文件。

## 7. 其它技能要点

- **🩺 Pre 建议**：有效字数 ≥50、拒绝「帮我写一份」；草稿 / 成品双模式报告；左侧卡片内联展示主题 / 阶段 / 逻辑链（本地 Mermaid 渲染）/ 完整正文；成果篮产出 `{主题}·Pre建议.docx`。
- **⏱ 日程提取**：从会议通知提取时间 / 地点 / 事件，生成可导入日历的 `.ics`；文件名按真实 `DTSTART` 的最早 / 最晚日期计算，例如 `1022-1201日程.ics`。
- **📝 复盘总结**：核心层 `summary_skill.run_summary(chat_history, api_key)`（不 import `streamlit`），Prompt 要求「✅ 肯定 / ❌ 否定 / ⏳ 搁浅」三栏复盘并输出 `[FILENAME: ...]` 协议行；黑盒负责清理文件名（非法字符 / Windows 保留名 / 超长）、删除 FILENAME 行、把 Markdown 转成 Word。四条入口（左侧卡片召唤 / 弹窗手动选 / 自动路由 / 🛑 总结会议）共用同一黑盒与同一结果写回逻辑。
- **🔎 深度调研**：核心层 `research_skill.run_skill(topic, api_key)`（不 import `streamlit`，Prompt 为根目录 `SKILL_research.md` 原文 + 八维输出契约），返回 `{text, mermaid_code, word_bytes}`；代码会清洗前言 / 结尾客套、提取唯一 Mermaid 关系图、做八维结构自检（八个 `###`、数据来源、表格数量、可信度标签、字数），不合格自动发起 1 次格式修复，仍不合格则拒绝生成 Word；网页层只负责调用、左侧预览与成果篮写回。

## 8. 离线 Mermaid 与部署清单

Pre 诊断的逻辑链由随包交付的本地脚本渲染，**不请求任何外部静态资源**：

- 资源文件：`static/mermaid.min.js`（2,571,900 bytes / 约 2.45 MiB，随包交付）；
- 静态服务：`.streamlit/config.toml` 已开启 `enableStaticServing = true`，Streamlit 会把 `./static` 映射到 `/app/static/`；
- iframe 引用：`/app/static/mermaid.min.js`（路径基于 `app.py` 所在目录计算，`os.path.dirname(os.path.abspath(__file__))`）；
- 渲染方式（v7）：`components.html(..., height=450, scrolling=True)` **固定 450px 高度**，Expander 展开 / 收起时不会塌陷为 0；iframe 内部用 `setTimeout(..., 200)` 延迟 200ms 再初始化 Mermaid，确保 DOM 与本地脚本完全就绪；
- 主题：`mermaid.initialize` 锁定 `theme: "default"`，背景透明，不遮挡卡片样式；
- 降级：`render_mermaid()` 最外层 try-except；若 `static/mermaid.min.js` 缺失 / 组件异常，自动改用 `st.markdown("```mermaid ...```")` 展示源码，不会导致页面报错；
- 内网 / 断网环境可用（只要浏览器能访问本机 Streamlit 服务即可）。

## 12. 已知边界

- **反馈只在聊天里**：v6 沿用 v5 的「零原生提示」，后台失败原因、总结失败原因都只出现在 AI 聊天气泡里；如果聊天区被滚走，需要往上翻。
- **静默轮询延迟**：聊天 / 成果篮各自每 2 秒同步一次，不是 WebSocket 实时推送；左侧面板平时不重绘，只有新数据到来时由 watcher 触发一次整页刷新（最多约 2 秒延迟）。
- **左侧指纹门控的粒度**：watcher 只比较「数量 + 最新一条 id（日程为标题/开始时间）」；仅修改已有条目内容（例如别的成员勾选任务、改已有任务标题）不会改变指纹，左侧面板不会自动重绘，刷新页面后可见。新增文件 / 任务 / 日程 / 成员会正常触发。
- **展开状态不会被自动改变**：左侧卡片只在「首次进入且已有历史」时默认展开；之后由用户手动控制。后台生成新内容时卡片保持当前状态——原本收起的不会自动弹开，需要手动展开查看新预览。
- **后台任务只在当前进程内**：召唤任务由守护线程执行，Streamlit 进程重启 / 崩溃会中断进行中的任务，重启后房间数据（内存态）也会清空。
- **会议总结仍为同步执行**：点「🛑 总结会议」后页面会等待总结完成（没有任何加载圈），完成后群内出现 AI 气泡、成果篮出现 Word；期间请勿重复点击。通过召唤弹窗走「📝 复盘总结」则是后台线程执行，弹窗秒关、结果稍后到达。
- **服务端仍保留任务状态字段**：`ServerState` 里会写入 `running / done / error` 供内部与测试使用，但页面不再展示状态条。
- **进程内存储**：群、成员、消息、任务、日程、成果与 API Key 都保存在当前 Python 进程内存，重启后清空；没有数据库、用户注册、权限与审计。
- **无用户体系**：身份靠昵称 + 邀请链接区分，同名成员会被视为同一人；没有登录、鉴权与操作审计。
- **BYOK**：所有真实 AI 调用（含大模型意图路由）都使用群主创建房间时填写的 Key；Key 只存在于进程内存，不落盘、不进日志与文件。
- **路由是「判断」不是「执行」**：自动识别只决定交给哪个技能；路由失败会兜底为本地占位调研（不调用模型、不花钱），可能把本应走其他技能的材料交给占位内容，此时请手动指定技能重试。
- **路由只读材料开头**：大模型路由只读合并材料的前 6,000 字符，超长材料的后半段不参与意图判断；真正的技能调用仍拿完整材料（任务拆解 19,900 字 / 深度调研 11,800 字网页层截断）。
- **静态资源必须随包**：`static/mermaid.min.js` 缺失时 Pre 逻辑链与调研关系图降级为 `st.markdown` 源码块；部署时不要漏打包该文件与 `enableStaticServing` 配置。
- **深度调研较慢且消耗 token**：一次完整八维报告通常需要 30–120 秒、1–2 次 DeepSeek 调用（格式自检不合格会重试一次）；后台线程执行，期间请勿重复提交；路由兜底不走真实调研，但手动选择 / 路由命中会真实计费。
- **调研 Prompt 文件必须随包**：`research_skill.py` 运行时读取同目录 `SKILL_research.md`；漏打包会直接报「缺少 Prompt 文件」。
- **任务卡不产出文件**：任务卡只留在左侧卡片内，成果篮不出现任务卡文件。
- **非流式**：DeepSeek 调用为一次性请求，不是逐字流式输出。
- **勾选同步时机**：勾选写回服务端，但页面由 Streamlit rerun 驱动，其他成员需刷新 / 下一次交互才能看到新进度（不是 WebSocket 实时推送）。
- **文件与文本限制**：仅支持 `.docx / .pptx / .xlsx / .txt / .md` 附件；扫描版 / 图片型 PPT 提取不到文字；单文件上传上限受 Streamlit `maxUploadSize = 5`（MB）限制；合并材料超 30,000 字符截断；任务拆解进入技能前 `len > 19,900` 材料会截到 19,900 字并附系统提示（技能核心层 20,000 字硬上限）。
